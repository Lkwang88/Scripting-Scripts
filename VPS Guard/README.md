# VPS Guard

偶尔瞄一眼的 VPS 红绿灯。主屏小组件显示每台机器的在线状态，主 App 里管理机器和调参数。

不是生产监控——不做秒级轮询，不做告警推送。定位是「有台机器没流量了，我过几天能发现它不通」。

## 功能

- 台数不限，随时增删；别名可改
- 地址支持 IPv4 / IPv6 / 域名（域名走 DoH 解析，换 IP 能看出来）
- 归属地自动获取（中文地名 + 国旗），添加时查一次并缓存
- 三种探测方式：TCP 端口（默认）、HTTP(S)、ICMP ping（需真机支持）
- 失败重试 + 摇摆抑制 + 指数退避，参数全部可调
- 288 点历史（5 分钟粒度 × 24 小时），带可用率和 sparkline
- 小组件支持 small / medium / large / 锁屏，排版按台数自适应

## 文件

| 文件 | 作用 |
|---|---|
| `script.json` | 项目描述（官方必需） |
| `index.tsx` | 主 App：列表、编辑、详情、设置 |
| `widget.tsx` | 主屏小组件 |
| `types.ts` | 数据模型与默认配置（模型的唯一真相来源） |

业务逻辑集中在 `.ts` 模块里，`index.tsx` 和 `widget.tsx` 只做各自宿主的适配——这是官方规范要求的分层。

## 三个关键设计

**小组件不能做秒级轮询。** `widget.tsx` 是一次性渲染，`Widget.present()` 调用后上下文立即销毁，hooks 全部无效。刷新由 WidgetKit 调度，`reloadPolicy` 只是建议，实际是 15 分钟量级。所以小组件是显示层，读 `Storage` 里的快照；探测在主 App 和小组件刷新时机里做。

**用 fetch 的失败速度反推在线。** Scripting 没暴露原始 socket。但只要对方 TCP 栈给了任何回应，机器就是活的：端口开着是 HTTP 就拿到响应；开着但不是 HTTP（SSH 22）会握手后很快解析失败；端口关着内核回 RST 也很快；只有机器真死了才一路耗到超时。所以判定规则是 **快速失败 = 在线，超时 = 离线**。这比 ICMP 可靠——很多机房默认丢 ICMP。

**哨兵防假阳性。** 上面的规则前提是手机有网。地铁里没信号时所有机器都会超时，十台一起变红纯属冤枉。所以每轮先探一次哨兵地址，不通就整轮作废，界面显示「本机无网络」。

## 参数说明

设置页可调，默认值在 `types.ts` 的 `DEFAULT_SETTINGS`：

| 参数 | 默认 | 说明 |
|---|---|---|
| `timeoutSec` | 5 | 单次探测超时，同时是「离线」的判定门槛 |
| `retries` | 2 | 一轮里失败后额外重试几次 |
| `retryGapMs` | 700 | 重试基础间隔，第 n 次等 n 倍 |
| `failThreshold` | 2 | 连续失败几轮才判离线（没到就先标黄灯） |
| `backoffBaseMin` / `backoffFactor` / `backoffMaxMin` | 5 / 2 / 60 | 离线后的指数退避 |
| `degradedMs` | 400 | 延迟超过这个值显示为「慢」 |
| `widgetMaxProbes` | 12 | 小组件单次最多探几台 |
| `historyPoints` | 288 | 历史保留点数 |

## 待真机验证

装好后需要在设备上确认的事（这些在桌面端无法测）：

- **ICMP 是否可用**：代码会自动跑一次 `ping -c 1 127.0.0.1` 探测 `ios_system` 是否内置 `ping`，结果缓存。不可用时 ICMP 选项会自动降级到 TCP。
- **小组件渲染**：必须加到主屏才算验证，App 内预览只是近似（官方明确说明对齐、圆角、尺寸会有差异）。
- **各尺寸排版**：small / medium / large / 锁屏需分别确认。
- **探测时间预算**：小组件里有硬预算，超时会提前收工并保留已有结果。真机上确认不会被系统杀掉。
